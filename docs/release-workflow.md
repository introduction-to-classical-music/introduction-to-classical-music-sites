# 站点发布工作流

## 一次完整发布的顺序

1. 在安装版工作副本中完成内容更新
2. 导出并审计根路径站点
3. 用本仓库同步该版本站点到 `site/v*` 和 `site/current`
4. 生成 `robots.txt / sitemap.xml / 404.html`
5. 用本地静态服务器模拟检查
6. 在临时 library 副本中生成 Pages 子路径站点
7. 使用 `publish-pages.ps1` 预览并显式推送 `pages`
8. 上传根路径站点到阿里云 `OSS`
9. 刷新 `CDN`
10. 做公网抽样验收

## 推荐命名

- 版本归档：`site/v0.1.0`
- 当前准备上线版本：`site/current`

## 每次发布至少检查

- 首页
- 关于页
- 作曲家目录页
- 指挥目录页
- 搜索页
- 至少一条录音页
- 样式和图片资源
- 404 页面

## 禁止事项

- 不要把桌面应用源码放进这个仓库
- 不要把构建缓存和临时目录放进这个仓库
- 不要把本地磁盘路径暴露到公网站点
- 不要把测试专栏和测试链接一起带上线
- 不要把根路径站点直接发布到 Pages 子路径
- 不要在未审计或未确认差异前传入 `-Publish`
