# 阿里云 `OSS + CDN` 上线方案

## 目标架构

推荐采用下面这条最直接、最稳妥的静态站点发布链：

1. 本地维护个人资料库并构建站点
2. 将站点归档复制到本仓库
3. 在本仓库完成上线前审计
4. 上传到阿里云 `OSS`
5. 用阿里云 `CDN` 加速并绑定域名
6. 开启 `HTTPS`

## 为什么推荐这个方案

- 不需要自建服务器进程
- 站点是纯静态页面，和 `OSS` 的能力完全匹配
- 成本低，维护简单
- 方便做版本回滚
- 后续页面量继续增长时，`CDN` 也更稳

## 本项目已满足的条件

- 站点已经可以作为纯静态文件集部署
- 首页、关于页、作曲家页、录音页、样式资源都能直接返回
- 站点源数据与桌面应用源码已经分离

## 上线前本地还需要完成的事项

- 运行站点审计脚本，确认不存在：
  - `localhost`
  - `127.0.0.1`
  - 本地磁盘路径
  - `__local-resource`
  - 测试专栏或测试链接
- 在拿到正式域名后生成：
  - `robots.txt`
  - `sitemap.xml`
  - `404.html`
- 明确部署根路径就是域名根目录

## 阿里云侧需要准备的事项

- 域名
- 备案
- `OSS` Bucket
- `CDN`
- `SSL/TLS` 证书
- 域名解析

## 建议的 OSS 与 CDN 配置

### OSS

- 存储类型：标准存储
- 读写权限：公共读（若通过 CDN 对外）
- 开启静态网站托管
- 默认首页：`index.html`
- 默认错误页：`404.html`

### CDN

- 回源地址：对应 `OSS Bucket`
- 回源协议：跟随请求或强制 HTTPS
- 缓存建议：
  - `HTML`：短缓存
  - `CSS/JS/字体/图片`：长缓存
- 开启压缩：`gzip / brotli`

## 安全建议

### 项目范围内

- 公网站点默认排除本地资源链接
- 所有外链继续带 `rel=\"noreferrer\"`
- 内容里不放私有文件路径

### 平台范围内

- 强制 HTTPS
- 配置基础安全响应头
- 定期备份站点归档
- 保留上一版站点用于快速回滚

## 推荐的回滚方式

- 仓库里同时保留 `site/current` 和 `site/<version>`
- 每次上线新版本前，把旧版完整保留
- 如果新版本出问题，直接把上一个版本重新同步到 OSS 即可
