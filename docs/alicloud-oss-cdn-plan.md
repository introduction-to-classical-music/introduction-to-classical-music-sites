# 阿里云 `OSS + CDN` 上线方案

## 目标架构

建议采用下面这条最直接、最稳定的静态站点发布链：

1. 在个人资料库工作区中完成内容更新并构建站点
2. 将站点归档复制到本部署仓库
3. 在本仓库完成上线前审计
4. 上传到阿里云 `OSS（Object Storage Service，对象存储）`
5. 用阿里云 `CDN（Content Delivery Network，内容分发网络）` 加速并绑定域名
6. 启用 `HTTPS（Hypertext Transfer Protocol Secure，安全超文本传输协议）`

## 为什么推荐这条链路

- 不需要长期运行服务器进程
- 站点本身是纯静态页面，与 `OSS` 的能力完全匹配
- 成本低，回滚简单
- 适合按版本归档和逐步发布
- 后续页面数量继续增长时，`CDN` 更容易扩展

## 当前项目已经满足的条件

- 站点可以作为纯静态文件集合部署
- 首页、关于页、目录页、录音页、样式资源都能直接返回
- 站点构建与桌面应用源码已经分离

## 本地上线前还要做的事

- 运行站点审计脚本，确认不包含：
  - `localhost`
  - `127.0.0.1`
  - 本地磁盘路径
  - `__local-resource`
  - 测试专栏或测试链接
- 在拿到正式域名后生成：
  - `robots.txt`
  - `sitemap.xml`
  - `404.html`
- 确认站点按“域名根目录”部署，而不是子路径部署

## 阿里云侧需要准备的内容

- 域名
- 备案
- `OSS Bucket`
- `CDN`
- `SSL/TLS` 证书
- 域名解析

## 推荐配置

### OSS

- 存储类型：标准存储
- 读取方式：配合 `CDN` 对外提供
- 开启静态网站托管
- 默认首页：`index.html`
- 默认错误页：`404.html`

### CDN

- 回源地址：对应的 `OSS Bucket`
- 回源协议：建议 HTTPS
- 缓存策略：
  - `HTML`：短缓存
  - `CSS / JS / 字体 / 图片`：长缓存
- 开启压缩：`gzip` 和 `brotli`

## 安全建议

### 项目范围内

- 公网站点默认排除本地资源链接
- 外部链接保持 `rel="noreferrer"`
- 页面内容中不要暴露本地磁盘路径

### 平台范围内

- 强制 HTTPS
- 配置基础安全响应头
- 定期备份站点归档
- 保留上一个稳定版本用于快速回滚

## 回滚建议

- 仓库同时保留 `site/current` 和 `site/<version>`
- 每次上线前完整保留旧版本
- 如果新版本出现问题，重新同步旧版本到 `OSS` 即可
